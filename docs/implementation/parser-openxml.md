# OpenXml Parser Subsystem (`Assistant.Parser.OpenXml`)

This document describes the design and implementation of the OpenXML template parser responsible for fulfilling **`REQ_MODEL_PARSE`** and the initial stage of **`REQ_TEMPLATE_VALIDATE`**.

---

## 1. Architectural Role

The official IK OVS template is provided as a versioned `.docx` document (`working_template.docx`). Structured fields and sections in the document are marked using Word's **Structured Document Tags (SDTs / Content Controls)**.

`Assistant.Parser.OpenXml` reads the OpenXML document, extracts all SDT elements, validates their aliases against domain rules, tracks duplicate occurrences, and returns a `TemplateInstance` DTO to the pipeline.

```
┌────────────────────────────────────────────────────────┐
│                  working_template.docx                 │
│              (OpenXML Document Package)                │
└───────────────────────────┬────────────────────────────┘
                            │ Read-Only Stream
                            ▼
┌────────────────────────────────────────────────────────┐
│               Assistant.Parser.OpenXml                 │
│                                                        │
│  ┌──────────────────────────────────────────────────┐  │
│  │              OpenXmlTemplateSdtParser            │  │
│  │   - Descendants<SdtElement>() traversal          │  │
│  │   - Read SdtId and Tag                           │  │
│  │   - Validate FieldAlias.TryCreate                │  │
│  │   - Compute OccurrenceIndex                      │  │
│  └──────────────────────────────────────────────────┘  │
└───────────────────────────┬────────────────────────────┘
                            │ TemplateInstance (Bindings + Diagnostics)
                            ▼
┌────────────────────────────────────────────────────────┐
│                   Assistant.Pipeline                   │
│                (TemplateRuntimeFactory)                │
└────────────────────────────────────────────────────────┘
```

## 2. Parsing Workflow (`OpenXmlTemplateSdtParser`)

The parser implements `ITemplateSdtParser.ParseAsync`:

1. **Document Loading**:
   Opens `WordprocessingDocument.Open(docxStream, isEditable: false)` in read-only mode to prevent document alteration or lock contention.
2. **Body Validation**:
   Checks for the existence of `MainDocumentPart.Document.Body`. If missing, returns immediately with diagnostic code `DOCX_NO_BODY`.
3. **SDT Traversal**:
   Enumerates all `SdtElement` descendants within the document body. This captures:
   - Inline content controls (`SdtRun`)
   - Block-level content controls (`SdtBlock`)
   - Table-cell content controls (`SdtCell`)
   - Row-level content controls (`SdtRow`)
4. **Property Extraction**:
   - `SdtId`: Unique integer ID generated by Microsoft Word.
   - `Tag`: String tag containing the domain alias (e.g., `IKOVS_PREFACE_BASIC-INFO_ORG_NAME`).
5. **Alias Validation**:
   - If the tag is empty or whitespace, records diagnostic `SDT_MISSING_TAG`.
   - Validates the tag format using `FieldAlias.TryCreate`. If it fails prefix or character set rules, records `SDT_INVALID_ALIAS` with the specific error.
6. **Occurrence Tracking**:
   If an alias appears multiple times in the document (e.g. headers, repeating summaries), the parser tracks its frequency via an in-memory dictionary and assigns sequential 0-based `OccurrenceIndex` values.
7. **Binding Assembly**:
   Constructs a `FieldBinding` DTO recording the alias, SDT ID, occurrence index, and content kind.

---

## 3. Diagnostic Reporting (`SdtParseDiagnostic`)

Rather than failing on the first malformed tag, the parser accumulates non-fatal diagnostics:

| Code | Severity | Description |
|------|----------|-------------|
| `DOCX_NO_BODY` | Fatal | The Word document package is corrupt or missing its main document body. |
| `SDT_MISSING_TAG` | Warning | An SDT exists in the document but has an empty or unconfigured tag. |
| `SDT_INVALID_ALIAS` | Warning | An SDT tag does not conform to the `IKOVS_*` naming rules defined in `FieldAlias`. |

These diagnostics are aggregated into `TemplateInstance.Diagnostics` and forwarded to `TemplateRuntimeFactory` in `Assistant.Pipeline` to provide full visibility into template integrity.

---

## 4. Requirements Traceability

- **`REQ_MODEL_PARSE`**: Provides the foundational extraction of all SDT content controls and binds them to strongly typed `FieldAlias` entities.
- **`REQ_TEMPLATE_VALIDATE`**: Verifies that the `.docx` package is valid OpenXML and that all content controls carry well-formed aliases.
